## 三、角色与控件联动（不是摆一张背景图）

- **fan hover**：当前扇瓣上抬 3px/描边略粗，连结线 `character_ui_connector_hairlines.svg` 小幅向对应方向平移，发丝叠层位移不超过 4px，600–900ms 缓动，不能覆盖字。
- **fan active**：相应按钮真实触发旧函数，扇面短暂增加细线/轻微阴影；动画不可阻塞业务动作。
- **进度更新**：状态徽章数值来自旧状态，吊坠仅微弱摆动；禁用状态与错误要有文字。
- **输入 focus**：输入边框变清晰，角落花饰微微展开，光标为真实 caret。
- **F8 开始**：工作流相关按钮的装饰线/一小片樱花产生微动；必须响应键盘和无障碍焦点。
- **`prefers-reduced-motion: reduce`**：全部浮动/摆动动画停止。

## 四、资源混合层级（顶部为视觉最前）

`z=0` 白色画布 → `z=1` 右侧面板/折扇 SVG → `z=2` 角色 PNG（仅越界头发覆盖面板边框，不遮正文）→ `z=3` 装饰连结风线/花枝（pointer-events none）→ `z=4` 真实可读文字和所有真实输入框/按钮 → `z=5` 弹窗/通知。对于角色覆盖扇框的部分，用局部 clip/mask 或独立发丝 overlay，不可整张人物硬覆盖右侧工作区。

## 五、实现顺序与验收

1. 从用户代码目录读取实际 UI 结构，先列出旧函数/快捷键/变量/持久化格式及对应新组件 ID。只有截图时先要求用户上传项目源代码，不能声称已改代码。
2. 保留原驱动层，用视觉组件层包裹；先迁移功能，不触碰外部键盘、剪贴板、DOCX、Google Docs 的实现。
3. 使用现成 SVG 和 4K PNG；不允许把截图作为整体背景偷懒，也不允许把新图里文字烘焙成 PNG。
4. 对照表逐项测试，输入/保存/恢复/错误/导出/校验/Tab/快捷键/高 DPI/中英文换行均通过后再收尾。
5. 1280px 以下将角色弱化或折叠为头像并让扇形重新布局；文档兼容按钮允许分行和容器滚动，不可压缩到无法点击。
